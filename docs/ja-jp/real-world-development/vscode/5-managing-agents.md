GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、これらの操作をリアルタイムで確認できます。差分をその場でレビューし、個々の変更を適用または取り消し、フォローアップのプロンプトで結果を調整したり、作業を広げたりできます。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル変更をレビューして適用する。
- セッションの途中で指示し、ハイコントラストモードに加えてライトモードを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を始めずに、既存のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが確認するファイル、実行するコマンド、提案する編集内容が順に表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの実行を確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を適用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードを実装し、変更の概要を最終メッセージで報告するまで待ちます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話にライトモードの切り替えを追加します。同じチャットを続けることで、エージェントは変更したコンポーネント、スタイル、ローカルストレージのパターンなど、前の作業のコンテキストを保持します。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードと同様に、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合 (例: 切り替え UI を意図しない形で再構成しようとした場合) は、入力欄の横にある **Stop** で停止し、明確な指示を追加して再度依頼できます。

> [!TIP]
> 作業中のセッションに追加の指示を送ると、最初からやり直すより短時間で調整できます。たとえば「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」、「既存の設定パネルにライトモードを追加し、3つ目の切り替えを作らない」、「両方の切り替えにキーボードショートカットも追加する」といった変更を依頼できます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれるはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保持) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して指示する方法を確認しました。ファイル編集を確認して適用または取り消し、フォローアップのプロンプトでコンテキストを保ったまま作業を広げました。

このレッスンでは、エージェントの作業をリアルタイムで監視し、個々の変更を適用または取り消し、作業中に指示を追加する方法を学びました。次は、アクセシビリティ作業を pull request として公開し、[このラボで作成したカスタムエージェントの変更をレビューします][next-lesson]。
